03

每次学完，用这套流程

  1. 在电脑上写，并实际运行

    用 VS Code 新建 .py 文件；例如 default_arguments.py。先试一个正常输入，再试一个边界输入。不要上传自己没运行过的结果。

  2. 打开 GitHub 对应的主题目录

    从上方卡片点击“打开文件夹”。接着选 Add file → Upload files，上传练习文件。多文件程序创建独立子目录并附运行说明。

  3. 提交时说清楚变化

    填写 Add default argument practice 或 Fix empty cart total，然后 Commit changes。一次围绕一个实际变化；不用为刷贡献格子拆分无意义提交。

  4. 补一条真实学习记录

    编辑 docs/LEARNING_LOG.md：代码路径、遇到的问题、原因、修复和验证。可以中文写；课程或 AI 帮助也如实标明。没有问题可写自己实际观察到的行为。

  5. 成果变化时，更新入口

    有新增脚本时更新课程索引与首页数量；做出值得展示的改进时替换精选链接。计划项只有实际完成并验证后才改状态。

已经使用本地 Git / VS Code 时

先同步仓库，旧根目录脚本已经移动。下面是操作示例；必须先自己创建示例文件才可运行和暂存。

git pull --ff-only
# 在对应目录中创建练习后再运行：
python3 course/03_functions_modules/default_arguments.py
python3 -m unittest discover -s tests -v
git status
git add course/03_functions_modules/default_arguments.py docs/LEARNING_LOG.md
git commit -m "Add default argument practice"
git push

如果 pull 提示本地改动或冲突，先保留并检查你的代码。只暂存这次要提交的文件，避免误传本地资料。不会 Git 命令时，可以继续用网页上传。

04

提高展示价值：让结论有证据

整理可以降低阅读成本，但不能保证面试转化率。能增强说服力的是：你解决了什么问题、实现了哪些部分、怎么确认它有效。

现在就能做

把一个练习讲清楚

解释小吃摊如何使用字典、为何会累计金额，展示一组真实输入和输出。学完函数后重构一个逻辑，再为边界条件加检查，保留前后变化。

申请前要补齐

让独立作品成为主入口

建议准备 2 个能解释、有验证的独立作品。课程仓库作为成长证据；简历的主要项目链接指向可以快速演示的应用或案例说明。

独立 AI 应用的展示条件

真实且明确的使用场景、可复现的安装与运行、演示、你自己的技术选择、固定测试样本、失败案例，以及实际测得的效果、延迟和成本。

简历什么时候写它

现阶段可以如实写“Python 基础练习与学习记录”，但不建议把跟课小游戏包装成应用 AI 工程经验。完成独立应用后，再写问题、个人贡献和实际结果。

以后写简历可用这个结构：为【具体使用者】解决【问题】，用【技术】实现【功能】，在【实际测试样本】上得到【真实结果】。括号里没有证据的内容先不写。

07

你可能会遇到的情况

两个购物车为什么都保留？

single_item_cart.py 是输入单件商品单价和数量；shopping_cart.py 是循环收集多件商品。它们代表不同学习阶段，不是重复文件。

课程天气 App 能放进 projects 吗？

按教程完成的天气 App 放在 course/08_gui/。独立选择问题、设计实现并记录个人贡献后，可以另建独立项目，清楚注明借鉴和扩展部分。

现在的代码有问题，要不要隐藏或删除？

先理解并修复，再记录一次真实的输入、原因和验证。现有脚本仍有数字输入异常、负价格等局限，已经在首页列明。保留历史，主页展示当前更成熟的成果。

README 上要放“精通 AI”“8 个月成为工程师”吗？

写目标和当前证据。目标是 2027 年 7 月左右争取应用 AI 实习；现在是 Python 基础学习阶段。未来功能标计划，完成后再更新。

GitHub 为什么只显示 HTML 源码？

GitHub 的普通文件页通常不直接执行 HTML。下载这份文件并双击，用 Chrome 或 Safari 打开即可；此指南不需要部署或安装依赖。

检查怎么运行？能证明所有程序都没问题吗？

在仓库根目录运行下面命令。当前 6 个回归检查只覆盖选定案例，不代表所有练习或所有输入都正确。

python3 -m compileall -q course tests
python3 -m unittest discover -s tests -v
